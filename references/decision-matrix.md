# 决策矩阵：维度 × 架构适配评分

## 评分规则

每个维度对每种架构给出适配分（1-5）：
- 5 = 最佳适配
- 3 = 可用但有短板
- 1 = 不适配

## 问卷→评分流程

### Step 1: 收集业务特征（8个维度各选一个等级）

```
1. 任务复杂度: 低(单步骤) / 中(多步骤) / 高(多步骤+多分支+迭代)
2. 子任务耦合度: 独立 / 顺序依赖 / 强耦合共享上下文
3. 流程确定性: 高(固定路径) / 低(动态路由)
4. 错误容忍度: 低(必须精确) / 高(可试错)
5. 人工介入需求: 少(全自动) / 多(需审批)
6. 实时性要求: 高(秒级) / 低(可等)
7. 领域专业度: 单一 / 多样
8. 可扩展性: 低(固定范围) / 高(快速迭代)
```

### Step 2: 查矩阵打分

将用户选择的每个维度等级对应到矩阵行，给6种架构各累加得分。

### Step 3: 计算推荐

- 总分最高的架构 = **主推荐**
- 总分差距 < 3 的 = **可选替代**
- 输出推荐理由 + 架构图 + 工作流设计要点

### Step 4: 附加建议

根据得分分布给出：
- 如果某维度得分极端偏离 → 提示风险
- 如果两种架构总分接近 → 给出混合方案
- 给出对应架构的工具链建议

## 问卷简化版（快速判断）

如果用户不想逐项选择，用3个核心问题快速判断：

**Q1: 你的任务有几个步骤？**
- 1-2步 → 单体倾向 +30
- 3-5步有固定顺序 → 流水线倾向 +30
- 不确定，需要判断 → 编排倾向 +30

**Q2: 做错了后果严重吗？**
- 严重 → 层级倾向 +30
- 不严重 → 去中心化/黑板倾向 +20

**Q3: 涉及几个不同领域？**
- 1个 → 单体倾向 +20
- 2-3个 → 编排倾向 +20
- 很多且需要互相参考 → 黑板倾向 +20
